# Алгоритмы и подготовка к защите

Обозначения: n — число элементов; V, E — вершины и рёбра; h — высота дерева;
L — суммарная длина строк. Оценки хеширования ожидаемые, амортизированные,
при контролируемом заполнении; произвольная строка хешируется за O(длины строки).

## 1. Зависимости задач

1. Собственная хеш-таблица сопоставляет именам номера вершин.
2. Для каждой задачи сохраняются задачи, от которых она зависит.
3. Итеративный DFS использует собственный стек на связном списке.
4. Цвета: белый — не посещали, серый — находится в текущем пути DFS,
   чёрный — полностью обработали. В стеке хранятся события входа и выхода.
5. Повторный вход в серую вершину означает цикл. При выходе задача добавляется
   в результат: все её зависимости уже выполнены.

Время O(V + E) без стоимости строковых ключей. Память O(V + E): граф,
цвета и стек отложенных событий. Это именно стековый обход; рекурсия не используется.
Возвращаемый порядок может быть не единственным.

Возможная модификация: выводить сам цикл, сохраняя родителей DFS.

## 2. Множество

Множество оборачивает собственную хеш-таблицу «строка → пустое значение».
Добавление обновляет уже имеющийся ключ, поэтому дубликатов нет.
Удаление ставит метку DELETED: обнуление ячейки оборвало бы цепочку поиска
коллидирующих ключей. Поиск идёт до совпадения, пустой ячейки либо полного цикла.

Ожидаемо O(1) для добавления, удаления и проверки ключа ограниченной длины;
рост таблицы даёт амортизированную оценку. Худший случай — O(n).
Память O(n) для таблицы без учёта длины строк и запасной ёмкости после удалений.
Сохранение JSON требует линейного обхода данных; сортировка для стабильного файла
добавляет O(n log n) для изменяемого множества.

Возможная модификация: объединение, пересечение и разность множеств.

## 3. Инопланетный геном

В множество из задания 2 заносятся все двухсимвольные подстроки второго генома.
Затем каждая соседняя пара первого генома проверяется на наличие. При совпадении
ответ увеличивается на единицу; одинаковые пары первого генома не удаляются.

Время O(|a| + |b|), память O(min(|b|, 26²)), так как возможны только 676 пар.
Направление сравнения существенно: степень близости a к b может отличаться от b к a.

Возможная модификация: сравнивать фрагменты длины k вместо пар.

## 4. Контрольная по ударениям

Словарь помещается в Array из личной ЛР1. Из массива строятся два множества:
слова в нижнем регистре и точные допустимые написания с ударением.
Для каждого слова текста сначала считаем заглавные буквы; должно быть ровно одно
ударение. Если слово известно, проверяем точное написание в множестве допустимых.
Неизвестное слово с одним ударением принимается.

Время O(L), дополнительная память O(размера словаря в символах),
плюс память считанного текста. Несколько разрешённых ударений одного слова
хранятся как разные точные написания.

Возможная модификация: выводить ошибочные слова и их позиции.

## 5. Восстановление дерева

Inorder корректного BST с уникальными ключами строго возрастает.
При обмене двух значений возникает одна инверсия между соседними элементами
inorder (обмен соседних) или две такие инверсии (обмен несоседних).
Первый ошибочный узел — предыдущий узел первой инверсии; второй — текущий узел
последней инверсии. Их значения меняются местами. Дополнительная проверка
отвергает деревья, не соответствующие условию; при ошибке обмен отменяется.

Обход итеративный. Поиск ошибочных узлов — O(n) времени и O(h) стека.
Полная реализация с проверкой через список inorder занимает O(n) памяти.
Форма дерева остаётся прежней: меняются только поля Data, а не Left/Right.
Балансировка при восстановлении не выполняется.

Возможная модификация: заменить проверку со списком на проверку с предыдущим
значением, уменьшив память самой операции до O(h).

## 6.1. Хеш-таблица

Основная функция — DJB2; вторая — FNV-1a. Размер — степень двойки.

- Линейное пробирование: `(h1(key) + i) mod capacity`.
- Двойное хеширование: `(h1(key) + i * step(key)) mod capacity`.

Во втором методе шаг нечётный: `h2(key) | 1`. Нечётное число взаимно просто
со степенью двойки, поэтому последовательность обходит все ячейки.
В коде индекс вычисляется последовательным прибавлением шага и маскированием.
Переполнение uint64 определено арифметикой по модулю 2^64 и не нарушает маску 2^k.

При приближении занятых ячеек и меток удаления к 70% таблица перестраивается.
Если живых ключей тоже много — размер удваивается; иначе очищаются метки удаления
при прежнем размере. Обновление существующего ключа не увеличивает размер.

Среднее время O(1), худшее O(n); расширение O(n) для ключей ограниченной длины.
Достоинства, ограничения и измерения — в HASH_ANALYSIS.md.

## 6.2. Иерархия сотрудников

Имена индексируются выбранной таблицей из 6.1. Строятся списки детей менеджеров.
Пара «человек → он сам» обозначает корень и не добавляет самоподчинение.
Проверяется, что у сотрудника не более одного менеджера. DFS со стеком
проверяет отсутствие циклов и получает постпорядок.
В постпорядке список каждого ребёнка вместе с ним самим добавляется в список
менеджера. Списки и итоговые строки сортируются для удобного сравнения.

Построение графа и DFS — O(V + E). Пусть K — общее число пар «менеджер — косвенный
или прямой подчинённый» в выдаваемых списках. Объединение — O(K), память O(V + E + K).
Сортировка — O(V log V + сумма(k_v log k_v)). В цепочке K = O(V²), что неизбежно
при явном выводе всех списков. Если нужны только количества, можно заменить списки
суммой `count[v] = сумма(1 + count[child])` и получить O(V + E), плюс сортировку имён.

Возможная модификация: режим вывода только количеств для больших иерархий.

## 7. LRU

Хеш-таблица хранит значения и указатели на Node из LinkedList личной ЛР1.
Ключи хранятся в поле Data узлов; LRU использует исходные PushFront/PopBack
и перемещение известного узла через его ссылки Prev/Next.
Голова — недавно использованный, хвост — давно использованный.
GET переносит найденный узел в голову. SET обновляет существующий узел либо
добавляет новый в голову; при нехватке места удаляется хвост и его ключ из таблицы.

GET и SET ожидаемо амортизированно O(1); перестановка узла списка — строго O(1).
Худший случай хеширования O(c), c — ёмкость кэша. Память O(c) для кэша;
обработчик сохраняет ответы GET, поэтому дополнительно O(Q).
Промах GET не меняет порядок. SET существующего ключа обновляет его давность.

Возможная модификация: добавить PEEK без обновления давности или DELETE.

## Основные понятия к защите

- Алгоритм: конечная последовательность определённых шагов, решающая класс задач;
  свойства — определённость, дискретность, конечность, результативность, массовость.
- Алгоритм Евклида: пока b ≠ 0, заменить (a, b) на (b, a mod b); O(log min(a, b))
  делений для положительных чисел, оценка предполагает единичную стоимость деления.
- O — асимптотическая верхняя граница, Ω — нижняя, Θ — тесная;
  O(1), O(log n), O(n), O(n log n), O(n²), O(2^n), O(n!) — типичные классы.
- АТД задаёт значения и операции; структура данных — способ их хранения и реализации.
  Интерфейс отделяет использование от внутреннего устройства; инкапсуляция скрывает детали.
- Скалярные типы: числа, логические значения и т. п.; составные: массивы, записи,
  структуры. Динамические структуры могут изменять размер во время работы.
- Массив: индексный доступ O(1), поиск O(n), вставка в середину O(n), добавление
  в конец динамического массива амортизированно O(1).
- Связный список: доступ и поиск O(n); вставка/удаление по известному узлу O(1)
  при наличии нужных ссылок. Односвязный хранит Next, двусвязный ещё Prev;
  кольцевой замыкает последний узел на первый.
- При работе со списком учитываются пустой список, единственный элемент,
  изменение головы/хвоста и согласованность прямых/обратных ссылок.
- Вставка: в начало, в конец, до известного элемента, после известного элемента.
  Удаление должно обновить ссылки соседей и голову/хвост.
- Стек — LIFO, очередь — FIFO. Push/pop стека и enqueue/dequeue очереди
  на подходящем связном списке с головой/хвостом выполняются за O(1).
- Дерево: корень, узлы, рёбра, родители, дети, листья, поддеревья, высота и глубина.
  В бинарном дереве до двух детей; BST дополнительно задаёт порядок ключей.
- Preorder: корень–лево–право; inorder: лево–корень–право;
  postorder: лево–право–корень. DFS использует стек, BFS — очередь.
- Full binary tree: каждый узел имеет 0 или 2 ребёнка. Complete binary tree:
  уровни заполнены, кроме, возможно, последнего, который заполняется слева направо.
- Поиск, вставка и удаление в BST — O(h), до O(n) без балансировки.
  При удалении: лист, один ребёнок, два ребёнка; в последнем случае берут
  inorder-предшественника (максимум слева) или преемника (минимум справа).
- AVL поддерживает разность высот поддеревьев в пределах 1 вращениями;
  красно-чёрное дерево использует цвета и ограничения на пути. Высота обоих O(log n).
- Коллизия: разные ключи имеют один индекс. Цепочки хранят несколько элементов
  в контейнере ячейки; открытая адресация ищет другую ячейку последовательностью проб.
- Хеширование делением использует остаток от деления; метод умножения выделяет
  дробную часть произведения на константу. В этой работе используются строковые
  DJB2/FNV-1a и уменьшение по модулю размера.
- LRU удаляет давно не использовавшийся ключ, LFU — ключ с наименьшей частотой.

Это краткие опорные ответы; полный перечень тем защиты приведён в методичке.
