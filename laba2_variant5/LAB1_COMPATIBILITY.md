## Различие видов деревьев

В ЛР1 реализовано Complete Binary Tree: Insert вставляет по уровням слева направо, а не по сравнению ключей. В задании 5 ЛР2 на вход уже дано повреждённое бинарное дерево поиска. Поэтому сохранены исходные типы узлов и дерева, но загрузчик ParseTree устанавливает связи по префиксной записи с #. Использовать Insert для такого ввода нельзя: он изменил бы форму и смысл входного дерева.

Методы Insert, Find, IsComplete, Read и Print личной ЛР1 сохранены. Обработчик ЛР2 не требует полноты и не использует Read как inorder: для проверки порядка ключей есть отдельная функция Inorder в tasks/task5.go. Никакой AVL-балансировки и поля Height здесь нет.

Множество и хеш-таблицы добавляются в ЛР2, потому что в предоставленной ЛР1 их нет. LRU использует существующий двусвязный список совместно с новой таблицей.
