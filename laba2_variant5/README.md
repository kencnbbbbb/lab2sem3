# Лабораторная работа №2. Порядковый номер 5

Язык: **Go 1.21 или новее**. Сторонние пакеты не нужны.
Структура повторяет Go-версию присланного примера: `main.go` запускает задания,
`str/` содержит структуры данных, `tasks/taskN.go` — решения.

## Варианты

| Задание | Расчёт | Реализовано |
|---|---|---|
| 1 | 5 mod 10 = 5 | Проверка порядка выполнения задач, собственный стек |
| 2 | Общее | Множество: SETADD, SETDEL, SET_AT |
| 3 | 5 mod 6 = 5 | Инопланетный геном, множество из задания 2 |
| 4 | 5 mod 6 = 5 | Контрольная по ударениям |
| 5 | 5 mod 9 = 5 | Восстановление бинарного дерева поиска |
| 6.1 | 5 mod 2 = 1 | Линейное пробирование и двойное хеширование, эксперимент |
| 6.2 | 5 mod 9 = 5 | Количество и списки подчинённых сотрудников |
| 7 | 5 mod 2 = 1 | LRU-кэш |

Вариант «*» (Хаффман) не выполняется: рейтинг 4–5 прошлого семестра не относится к студенту.

## Сборка и запуск

Откройте терминал в этой папке:

```sh
go build -o laba2 .
go test ./...
go vet ./...
```

Либо `make`, `make test`, `make check`, если установлен Make.
На Windows при сборке можно указать `-o laba2.exe`, а в командах использовать `./laba2.exe`.

Без параметров `./laba2` открывает меню. Выберите номер задания, введите его данные
и завершите ввод отдельной строкой `END`. После результата можно выбрать следующее
задание; `0` завершает программу. В задании 2 меню отдельно спрашивает файл и запрос,
в задании 6.1 данные не нужны.

Для проверки примеров удобнее режим `--task`: он читает вход из файла или до конца
стандартного ввода, без `END`.

```sh
./laba2 --task 1 < examples/task1_possible.txt
./laba2 --task 1 < examples/task1_cycle.txt
./laba2 --task 3 < examples/task3.txt
./laba2 --task 4 < examples/task4.txt
./laba2 --task 4 < examples/task4_second.txt
./laba2 --task 5 < examples/task5.txt
./laba2 --task 6.2 --method linear < examples/task6.txt
./laba2 --task 6.2 --method double < examples/task6.txt
./laba2 --task 7 < examples/task7.txt
```

## Форматы и ожидаемые результаты

### 1. Проверка порядка выполнения задач

Первая строка: число задач `N` и число зависимостей `M`. Далее `N` уникальных имён,
потом `M` пар `A B`, означающих **A зависит от B**. Разделители — любые пробелы и переводы строк.

```text
3 2
A B C
A B
B C
```

Результат:

```text
Возможно
C B A
```

Дополнительно к требуемому ответу выводится один допустимый порядок.
Для примера с циклом — `Невозможно`. Неизвестные имена и повторные имена задач — ошибка ввода.

### 2. АТД Множество

```sh
./laba2 --file data.json --query "SETADD myset apple banana apple"
./laba2 --file data.json --query "SET_AT myset apple"
./laba2 --file data.json --query "SETDEL myset apple"
./laba2 --file data.json --query "SET_AT myset apple"
./laba2 --file data.json --query "PRINT myset"
```

Проверки выведут `true`, затем `false`; PRINT выведет `banana`.
Повторное добавление не создаёт дубликатов. Удаление отсутствующего элемента допустимо.
Можно хранить несколько именованных множеств в одном файле.

Файл — JSON вида `{"myset": ["apple", "banana"]}`. Если его нет, первая операция
изменения создаёт файл. Существующий пустой или повреждённый файл вызывает ошибку,
чтобы случайно не затереть данные. Проверка наличия и PRINT файл не изменяют.
Запись выполняется через временный файл с последующей заменой.
Имена и элементы запроса — отдельные слова без пробелов. Одновременные записи
нескольких процессов не поддерживаются.

Операции самой структуры имеют ожидаемую амортизированную сложность O(1)
для ключей ограниченной длины; худший случай O(n). Полный консольный запрос
включает чтение/запись файла и не является O(1). Это разграничение принципиально:
абсолютную гарантию O(1) для произвольных строк обычная хеш-таблица не даёт.

### 3. Инопланетный геном

Две непустые строки из `A..Z`, каждая длиной до 100000. Пример `ABBACAB` / `BCABB`
даёт `4`. Повторяющиеся пары **первого** генома учитываются каждое вхождение:
`AAAA` / `AA` даёт `3`. Во втором геноме достаточно факта наличия пары.

### 4. Контрольная по ударениям

Число слов словаря `N`, затем `N` слов с одной заглавной буквой; после словаря —
проверяемый текст. Несколько вариантов ударения одного слова задаются отдельными
словарными словами. Для неизвестного слова требуется ровно одна заглавная буква.
Реализация поддерживает также регистр кириллицы.

Первый пример методички (`thE pAge cAnnot be fouNd`) даёт `2`,
второй (`The PAGE cannot be found`) — `4`.

### 5. Проверка дерева

Методичка не задаёт формат ввода повреждённого дерева. Здесь используется
**префиксный обход (корень, левое поддерево, правое поддерево)**, символ `#`
обозначает пустого ребёнка. Это позволяет передать уже повреждённое дерево,
сохранив форму. Обычная вставка входных значений в BST здесь не подходит:
она сама построила бы корректное дерево и потеряла исходное повреждение.

```text
3 1 # # 4 2 # # #
```

Это дерево:

```text
    3
   / \
  1   4
     /
    2
```

Результат:

```text
Исправленное дерево (preorder): 2 1 # # 4 3 # # #
Inorder: 1 2 3 4
```

Меняются только значения двух узлов. Ссылки на детей не меняются.
Поддержаны соседние и несоседние в inorder переставленные узлы, включая корень.
У корректного дерева, пустого дерева, повторяющихся значений или повреждения,
которое не исправляется одним обменом, программа сообщает ошибку: это не условие
«ровно два различных узла поменяли значения». Дубликаты ключей BST не допускаются.

### 6.1. Сравнение хеширования

```sh
./laba2 --task 6.1 > HASH_RESULTS.csv
```

Результаты проведённого запуска уже включены в `HASH_RESULTS.csv`, пояснения —
в `HASH_ANALYSIS.md`. Оба метода реализованы в `str/open_hash.go`.
Есть вставка/обновление, поиск, удаление с метками и автоматическое расширение.

### 6.2. Количество сотрудников

Число пар `N`, затем пары `сотрудник менеджер`. Пример:

```text
5
A B
C B
D E
B E
E E
```

Результат:

```text
A-0
B-2: A C
C-0
D-0
E-4: A B C D
```

Считаются все прямые и косвенные подчинённые, сам сотрудник исключается.
Выводятся и количество, как в примере, и список, как требует текст условия.
`E E` обозначает корневого руководителя и не создаёт ребро к самому себе.
Сотрудник, встречающийся только как менеджер, также учитывается.
Поддерживается несколько независимых иерархий, одинаковые пары не дублируются.
Разные менеджеры для одного сотрудника и циклы считаются ошибками.
Параметр `--method linear|double` выбирает одну из реализаций задания 6.1;
по умолчанию используется `double`.

### 7. LRU-кэш

Сначала ёмкость `capacity` и число запросов `Q`, затем ровно `Q` операций:
`SET ключ значение` или `GET ключ`. Ключи и значения — целые 64-битные числа.
GET возвращает **значение**, как в примерах методички (в тексте условия написано
«ключ», что противоречит примерам). При отсутствии — `-1`.

Доступ GET и обновление SET делают элемент самым недавно использованным.
При заполнении вытесняется самый давно использованный. Нулевая ёмкость допустима:
ничего не сохраняется, все GET возвращают `-1`; отрицательная ёмкость — ошибка.
Пример из `examples/task7.txt` даёт `5 -1`.

## Файлы для изучения

- `ALGORITHMS.md` — алгоритмы, оценки сложности и вопросы для защиты.
- `HASH_ANALYSIS.md`, `HASH_RESULTS.csv` — сравнение двух методов хеширования.
- `TEST_REPORT.md` — проведённые проверки.
- `SOURCE.md` — источник базовых структур и перечень изменений.
- `*_test.go` — автоматические тесты, запускаются через `go test ./...`.

**Связь с ЛР1:** базовые структуры перенесены из предоставленной личной ЛР1
(Go-версия): массив, списки, стек, очередь и типы дерева. Исходники этих модулей
сохранены без изменений. Соответствие файлов и применение описаны в
`LAB1_COMPATIBILITY.md`. LRU использует тот же LinkedList и Node.

В ЛР1 дерево — Complete Binary Tree; в задании 5 ЛР2 требуется BST. Используется
та же структура Tree/TreeNode, но готовое повреждённое дерево загружается
по ссылкам, без вызова Insert из ЛР1: вставка по уровням не задаёт порядок BST.
Полнота дерева в этом задании не требуется. Проверяются порядок ключей и
восстановление обменом двух значений без изменения формы.
