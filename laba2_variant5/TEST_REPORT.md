# Результаты проверки

Дата: 2 ноября 2026 года. Среда: Go 1.26.2, macOS, arm64.
Проект использует возможности Go 1.21; отдельно на Go 1.21 и на других ОС не запускался.

Выполнены:

```sh
go build -o laba2 .
go test ./... -count=1 -v
go vet ./...
./laba2 --task 6.1 > HASH_RESULTS.csv
```

Все 16 тестовых функций прошли, `go vet` не сообщил замечаний.
Полный вывод последнего запуска находится в TEST_LOG.txt.

## Что проверено

- **Запуск программы:** сборка отдельного исполняемого файла; вызов каждого
  задания через командную строку; оба метода для 6.2; последовательный запуск
  заданий через меню; ошибки ввода завершают отдельный запуск ненулевым кодом.
- **Задание 1:** оба примера методички, цикл из одной вершины, общий предок,
  повторное ребро, пустой граф, неизвестное имя, цепочка из 10000 задач.
  Дополнительно 300 случайных графов сверены с независимым алгоритмом Кана.
  Для получаемых порядков проверено выполнение зависимостей.
- **Множество:** повторное добавление, удаление, отсутствие элемента;
  сохранение нескольких множеств между независимыми запусками программы.
  Неверный запрос и повреждённый файл не затирают исходные данные.
- **Геном:** пример с результатом 4, повторяющиеся пары, разные геномы,
  односимвольные строки и строка из 100000 символов.
- **Ударения:** оба примера с ответами 2 и 4; несколько допустимых ударений,
  неизвестные слова с 0, 1 и несколькими ударениями; кириллица.
- **Дерево:** попарные перестановки значений в нескольких деревьях, включая
  соседние и несоседние узлы inorder и корень. Проверены возвращение исходных
  значений и неизменность ссылок на детей. Некорректная запись, дубликаты,
  пустое/корректное дерево и неисправимое одним обменом повреждение отвергаются.
- **Хеш-таблицы:** по 30000 случайных операций вставки, поиска и удаления для
  каждого метода сверены со стандартной map в тестах. Проверены обновление ключа,
  пустой ключ, расширение, многократное удаление/повторная вставка и метки удаления.
  В рабочих алгоритмах вместо стандартной map используется собственная таблица;
  стандартная map здесь служит независимым эталоном.
- **Сотрудники:** пример методички с обоими методами хеширования,
  повторные пары, несколько независимых иерархий, циклы и два менеджера
  для одного сотрудника.
- **LRU:** оба примера методички, нулевая ёмкость, одинаковые числовые ключи
  `01` и `1`. Для ёмкостей от 0 до 7 выполнено по 5000 случайных запросов,
  ответы сверены с независимой реализацией на map и массиве давности.
- **Эксперимент 6.1:** выполнены все 12 сочетаний набора, заполнения и метода;
  счётчики проб и фактическое время сохранены в HASH_RESULTS.csv.

Тесты подтверждают проверенные сценарии, а не являются математическим
доказательством отсутствия всех ошибок. Базовые модули сверены с предоставленной личной ЛР1 побайтово; её тест
Complete Binary Tree включён и прошёл вместе с тестами ЛР2. Дополнительно проверено,
что LRU перемещает существующие узлы LinkedList из ЛР1, сохраняет их указатели
и согласованность ссылок при обновлении и вытеснении.
